## Gaps found (by reviewer role)

### Principal AI Engineer

rather than content hashes, index versions, blue/green), incremental updates (stable chunk ids, `diff_chunks`,
embedding cache, contextual-prefix re-embedding), deletion (logical vs physical, tombstone, four resurrection
paths, reconciliation), permissions (pre-filter, re-check at packing, never after generation, ACL change
propagation), multi-tenancy (shared index vs namespaces, rank fusion across partitions, noisy neighbors),
caching (three layers with keys and invalidation, generations, TTLs, what is never cached), observability
(span tree, metrics, freshness lag), cost and latency budgets (enforced stage deadlines, request deadline, cost
per answer), scalability (index sizing, Little's law), freshness SLOs, degraded modes, and evaluation in CI.

- The security bullet said the embedding cache "holds query texts as keys"; keys are SHA-256 hashes, while the
  real exposure is that values are vectors, which are partially invertible.

## Changes applied

Code:
- `guardrails/guardrails/tenancy.py`: `TenantScopedCache.discard(ctx, *parts) -> bool`, `discard_key(key) -> bool`,
  `keys()`, `clear() -> int`; `invalidate_tenant` and `clear` route through `discard_key`, the single override point
  for subclasses that keep per-key metadata. Per-key TTL was not needed in guardrails (P3 keeps TTL in its
  metadata). Tests +2 in `guardrails/tests/test_tenancy.py`.
- `p3-rag-assistant/rag_assistant/caching/caches.py`: `ScopedCache` overrides `discard_key` (drops metadata, then
  calls the public parent method); `_drop` delegates to it; `clear()` uses `super().clear()` and returns the count.
  No access to `_store` remains. This also fixes the `invalidate_tenant` phantom-hit bug. New
  `tests/test_p3_scoped_cache.py` (2 tests).
- `ragkit/ragkit/retrieval/pipeline.py`: first-stage jobs and the timed reranker call run via
  `contextvars.copy_context().run` (one copy per job, since a Context cannot be entered by two threads at once).
  Test `test_parallel_retriever_spans_keep_their_parent_across_the_thread_pool` covers the default pool, a shared
  executor, and the deadline path; I verified it fails when context copying is disabled. Ch 12's `_run_jobs`
  listing and prose updated (test count 77).
- `p3-rag-assistant/rag_assistant/api/app.py` + `config.py`: `create_app` raises at startup when `auth_secret` is
  the published dev default unless `allow_dev_auth_secret` (`RAG_ALLOW_DEV_AUTH_SECRET=true`); `DEV_AUTH_SECRET`
