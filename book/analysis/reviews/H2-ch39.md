## Gaps found (by reviewer role)

### Principal AI Engineer
- The brief's requirements are all present and tested: streaming API and UI, gateway and router,
  hybrid RAG with ACLs and citations, governed tools with approvals, P1 structured extraction,
  conversation and profile memory, three gated eval suites, OTel tracing, JWT auth with tenants,
  four-stage guardrails, scoped caches, Docker, Compose, k8s, two CI pipelines, and a cost ledger.
- Every code listing in the chapter matches the file on disk, checked line by line and in order by
  script. All test names cited in the chapter, README, solutions, roadmap, and matrix exist.
- The chapter and roadmap implied the capstone contains all six projects. The roadmap says "P5 and P6
  its agents". The capstone composes P1 to P4 only. Project 5, Project 6, MCP (Ch 18), the workflow
  engine (Ch 17), and Ch 38's durable runner are not used. No text said so or why.
- The readiness review was attributed to "Chapter 28's readiness questions", which do not exist.
- The tradeoffs section said "eleven packages"; the capstone depends on twelve.
- Exercise references said "extension project P1/P3", which collides with Project 1 and Project 3.

### Senior Software Architect
- **Security (latent):** `ToolLayer.approve` recorded the decision first. Then, if the requester's
  in-memory context was missing, it rebuilt one with a hard-coded scope set
  (`replies:send`, `tickets:write`, ...) and no groups, and executed. The executor re-runs policy with
  that context, so group-based checks (the contractor deny) and the requester's real scopes would be
  bypassed. The branch was unreachable only because approvals are in memory too. Practical exercise
  P1 asks for durable approvals, which would have made it live.
- Root spans did not follow Chapter 31's lineage conventions. `index.version` existed only as
  `version.index_version`, and agent requests had no `prompt.version`. Chapter 31's
  `telemetry.incomplete_rate` therefore rated every capstone trace incomplete (measured: 1.0).
- The final ACL check's `acl_violations` (ragkit) and abstention never reached span attributes, so
  Chapter 31's cross-tenant and abstention metrics could not see them.

### AI Educator
- The chapter's mapping of subsystems to chapters and packages is accurate, with one exception: no
  section explained what the capstone deliberately leaves out.
- Solutions match the exercise ids (K1-6, E1-4, P1-5, D1-3). Every API they name exists (checked).
- The roadmap checklist overstated two items:
  - "integration tests pass": the capstone has none; they are exercise P2.
  - "calibrated faithfulness judge": the lexical judge reports kappa 0.36 and is explicitly not
    trusted.
- The roadmap checklist had no alerting item, although the chapter teaches alerts.

### Production/SRE Engineer
- Runbook, dashboards, readiness table, two failure analyses, and the release gate (seen to fail)
  are present. The gate behaves as documented. Reference metrics reproduce exactly; only
  sub-cent cost figures differ.
- Alerts existed only as prose. Nothing proved they could be evaluated, and the trace-convention gap
  above would have made `telemetry_gaps` page forever.
- Test dependencies: Chapter 31's `metrics` module needs PyYAML, which was absent from the capstone's
  dev extras and the image.

## Changes applied

- **Approval fails closed** (`northwind_assist/tools/service.py`, `api/app.py`):
  - `approve` now looks up the requester context before recording a decision.
  - If the context is missing, it raises `requester_context_lost`, which the API maps to 409.
  - No decision is recorded and the approval stays pending.
  - New test `test_approval_fails_closed_when_requester_context_is_lost`.
  - The chapter listing was re-pasted from disk and the text explains the change.
  - The failure-mode and readiness rows were updated, and a threat-model row added.
  - Practical exercise P1 now requires persisting the requester context with each approval.
- **Chapter 31 conventions on the root span** (`orchestrator.py`):
  - The root now carries `index.version`, plus `prompt.id` and `prompt.version` for the workflow's
    registry prompt (`none` for workflows without one).
  - It also carries `response.abstained`.
  - On a final-check violation it adds `acl.violations` and `error.class=retrieval_contamination`.
- **Alerts as code:**
  - New `ops/alerts.yaml` in Chapter 31's format, with page and ticket rules matching the chapter's
    alert list, each with a runbook line.
  - New `tests/test_alerts.py` with three tests:
    - the rules load, and an unknown metric fails;
    - healthy traffic has zero incomplete traces and fires no rule;
    - an injected final-check violation fires `cross_tenant_retrieval`.
  - `pyyaml` added to the dev extras; ruff's isort list extended.
- **Chapter 39:**

  - Sentence on the chapters that shape the capstone without an import (1, 8, 10, 26, 28).
  - Readiness review re-attributed; twelve packages; "practical exercise P1/P3"; 67 tests.
  - Alerts paragraph rewritten around `ops/alerts.yaml` and the gap it exposed.
  - Root-span description updated.
- **README:** test counts, layout row for `ops/`, an alerts runbook entry, and checklist rows for
  alert rules and the fail-closed approval.
- **Roadmap:**
  - The project paragraph now says P1 to P4 are capstone parts, and that P5 and P6 are learning

  - Checklist wording now points to the README evidence table.
  - Integration tests are attributed to exercise P2, and CI wording covers the type check and the

## Second-pass findings

- All four roles were re-run on the edited files. Two wording fixes followed:
  - The first P1 acceptance draft claimed a role-revocation check that persisted scopes cannot
    provide.
  - The "contractor" example of the latent bug was wrong, because a contractor's send is denied
    before an approval exists. Both were reworded to what the code does.
- The ACL-disabled configuration still produces no trace-level signal, by design: the final check
  reads the same corrupted metadata. The new contamination alert covers only violations the final
  check catches. The chapter's second failure analysis already explains why the evaluation, not the
  trace, catches the metadata bug.

## Remaining open items

- `docker compose up` was not run: the pgvector and OTel collector images are not available locally
  and Docker Hub returns 503. The Project 3 backend against real Postgres and Redis remains
  unverified, as the README already states.
- No real-provider integration run: there is no key in this environment (exercise P2).
- Pending approvals and session windows are still in process memory. They now fail closed. Making
  them durable is exercise P1, a feature beyond a review fix.
- `ruff format` is not applied or enforced. Applying it would rewrite 34 files and every listing in
  the chapter, for no behavioral gain.
